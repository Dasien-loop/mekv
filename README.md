# Mekv

**简体中文** | [English](README_EN.md)

**让村民交易、耕种和铁傀儡生产成为工厂生产线的一部分。**

Mekv 将 Easy Villagers 的村民玩法与 Mekanism 的工业自动化结合起来。放入村民、接通能量，再配置交易或生产内容，即可通过多列处理、并行产出和物品输送建立可逐级扩展的生产线。

## 版本与分支

| 分支 | Minecraft | 加载器 | Java |
| --- | --- | --- | --- |
| `main`（当前分支） | 1.20.1 | Forge 47.x | 17 |
| `1.21.1neoforge` | 1.21.1 | NeoForge 21.1.x | 21 |

请按游戏版本和加载器选择对应文件，两个版本的 JAR 不能混用。下文配置默认值、具体列数和构建检查以当前 `main` 分支为准，另一分支的实现以其源码与发布文件为准。

## 主要内容

| 工厂 | 用途 | 工作准备 |
| --- | --- | --- |
| 交易工厂 | 自动执行村民交易，每列拥有独立输入、输出和交易选择 | 村民、有效工作站、交易材料和能量 |
| 耕种工厂 | 自动种植、生长并收获作物 | 村民、支持的种子或种植物品和能量 |
| 铁傀儡工厂 | 自动完成铁傀儡生产周期并输出掉落物 | 村民和能量 |

- **独立交易控制**：支持全局选择交易，也可分别选择、暂停或恢复每一列。
- **输入自动整理**：按完整交易份数分配相同材料，合并空闲列零头，并保留正在处理的交易所需材料。
- **自动化接口**：可配置物品与能量侧面，支持自动输出、Mekanism 物流相关设置及红石控制。
- **升级与管理**：提供升级窗口、等级安装器交互，以及所有者和安全设置。
- **可视化工厂**：玻璃窗口内展示村民及对应的工作站、作物或铁傀儡场景。
- **双语界面**：内置简体中文和英文语言文件。

## 环境与依赖

| 模组 | 是否必需 | 1.20.1 Forge | 1.21.1 NeoForge |
| --- | --- | --- | --- |
| Mekanism（通用机械） | 必需 | 10.4.16 及以上 | 10.7 及以上 |
| Mekanism Generators（通用机械发电机） | 必需 | 10.4.16 及以上 | 10.7 及以上 |
| Easy Villagers（简易村民） | 必需 | 1.0.0 及以上 | 1.0 及以上 |
| Mekanism Extras（通用机械扩展） | 可选 | 1.5.0 至低于 1.6 | 1.4.1 及以上 |

以上范围来自两个分支的依赖声明，不代表其中所有版本均已测试。所有依赖必须与所选 Minecraft 版本、加载器匹配，并满足各自的前置要求。

将 Mekv 和必需依赖放入游戏的 `mods` 文件夹；多人游戏需在客户端和服务端安装，并保持 Extras 的安装情况一致。AE2、JEI 等不是 Mekv 声明的必需依赖。

## 工厂等级

| 等级 | 交易列数 / 产出并行数 | 需要 Extras |
| --- | ---: | :---: |
| 基础 Basic | 3 | 否 |
| 高级 Advanced | 5 | 否 |
| 精英 Elite | 7 | 否 |
| 终极 Ultimate | 9 | 否 |
| 绝对 Absolute | 11 | 是 |
| 至尊 Supreme | 13 | 是 |
| 寰宇支配 Cosmic | 15 | 是 |
| 悖论无限 Infinite | 17 | 是 |

不安装 Extras 时提供三类、四级，共 **12 台工厂**；安装后追加四个高阶等级，共 **24 台工厂**，同时启用高阶配方。交易工厂的列数代表独立处理通道，耕种和铁傀儡工厂则以等级提高产出并行数，并非直接将单次周期缩短相同倍数。

可通过合成逐级升级，也可使用对应等级安装器潜行右键升级已放置的工厂。具体材料以游戏内配方为准。移除 Extras 前请备份存档并处理高阶机器，否则这些方块和物品将不再注册。

## 开始使用

1. 合成所需工厂并放置，为其配置能量输入和物品输入、输出面。
2. 放入 Easy Villagers 的村民物品，并按工厂类型补充工作站或种植物品。
3. 交易工厂需选择有效交易并输入材料；耕种、铁傀儡工厂在条件满足后自动工作。
4. 根据需要开启自动整理、自动输出，设置红石模式，并安装支持的升级。

### 交易自动化注意事项

- 每列只有一个输入槽，**需要两种不同物品的交易暂不支持**。
- 全局交易选择仅应用到空闲且没有输入的列。有输入或交易正在进行的列不能直接更换交易。
- 自动整理不会移动暂停列中的材料；恢复该列后会重新参与分配。真正不足一次交易的总余料会等待后续补料。
- 使用 AE2 等系统制作处理样板时，应按村民的**当前价格**填写材料数量。村民价格变化或缺货仍可能影响订单完成。
- 例如价格为 4 铁换 1 绿宝石时，250 次交易需要 1000 铁。启用自动整理后，空闲列中的零头会合并，不必给每列额外补铁。
- 若订单停滞，请检查暂停状态、当前价格、库存、能量、红石设置及输出空间。

## 升级插件

| 工厂 | 支持的升级 |
| --- | --- |
| 交易工厂 | 本模组的无限交易升级 |
| 耕种工厂、铁傀儡工厂 | Mekanism 速度、能量、消声升级 |

无限交易升级使交易工厂忽略村民库存限制，但**仍然消耗交易材料和能量**。插件可通过升级窗口安装、卸载，也支持持有可用插件潜行右键安装。

## 配置

配置文件在启动后生成于 `config/mekv-common.toml`。建议退出游戏或停止服务端后修改，再重启验证生效。

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `energyPerTrade` | 200 | 每次交易的基础能耗，FE |
| `energyPerGolem` | 1000 | 铁傀儡处理的基础能耗，FE |
| `energyPerCropAge` | 50 | 作物每次生长的基础能耗，FE |
| `energyPerHarvest` | 200 | 作物收获的基础能耗，FE |
| `tradeDurationTicks` | 15 | 单列交易耗时，允许 10–20 tick |
| `factoryEnergyCapacityMultiplier` | 1.0 | 工厂能量容量倍率 |
| `factoryEnergyTransferMultiplier` | 1.0 | 工厂能量接收速率倍率 |

实际能耗与容量还可能受支持的升级影响。部分生产与补货节奏沿用 Easy Villagers 配置，升级倍率计算使用 Mekanism 配置。20 tick 在正常游戏速度下约为 1 秒。

## 从源码构建

先选择目标分支：`main` 使用 JDK 17，`1.21.1neoforge` 使用 JDK 21。各分支的本地依赖不同，请按照对应 `build.gradle` 准备 `libs/` 中的 JAR，包括开发用的可选集成与辅助模组。

```bat
gradlew.bat build
```

Linux/macOS 使用 `./gradlew build`，产物位于 `build/libs/`。开发运行时可使用 `-PwithoutExtras` 排除 Extras；编译阶段仍需要 Extras JAR。

构建检查包含交易分配、界面布局、资源引用以及有/无 Extras 的 JVM 类加载测试。这些检查不替代游戏内联动和视觉实测。
